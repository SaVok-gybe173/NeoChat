# NeoChat server — Python port

Полный переезд серверной части NeoChat (изначально на C++) на Python 3
(asyncio, только стандартная библиотека, никаких pip-зависимостей).

Протокол общения с клиентом **не менялся**: TCP-сокет, каждое сообщение —
`[4 байта: длина, big-endian uint32][N байт: JSON в UTF-8]`. Это ровно то,
что делал оригинальный `Session.cpp` через `htonl/ntohl`, так что этот
сервер по проводу совместим с уже существующим клиентом.

## Структура

```
neochat_server_py/
├── main.py                  # точка входа (аналог src/main.cpp)
├── config.ini                # тот же формат, что и раньше
├── requirements.txt
└── neochat_server/
    ├── config.py             # загрузка config.ini (Config.hpp/cpp)
    ├── logger.py              # логирование в файл + консоль (Logger.hpp/cpp)
    ├── security.py            # хэш пароля + генерация токена (ICrypto/Sha256Hasher)
    ├── rate_limiter.py        # анти-брутфорс лимитер (RateLimiter.hpp/cpp)
    ├── database.py            # JSON-хранилище users.json/messages.json (JsonDatabase)
    ├── protocol.py            # фрейминг сообщений (длина+JSON)
    ├── session.py              # одно клиентское соединение (Session.hpp/cpp)
    ├── handlers.py             # вся бизнес-логика запросов (Handlers.hpp/cpp)
    ├── router.py                # диспетчер action -> handler (Router.hpp/cpp)
    └── server.py                # asyncio TCP-сервер (Server.hpp/cpp)
```

## Запуск

```bash
python3 main.py            # использует config.ini из текущей директории
python3 main.py path/to/config.ini
```

Файлы `data/users.json` и `data/messages.json` создаются автоматически.

Остановка — `Ctrl+C` (SIGINT) или SIGTERM: сервер закрывает все сессии,
сбрасывает базу на диск и завершает работу.

## Что изменилось по сравнению с оригиналом

- **Поток выполнения**: вместо потока ОС на каждое соединение (`std::thread`
  в `Session::start()`) — одна asyncio-задача на соединение в одном event loop.
  Из-за этого пропала нужда в мьютексах (`std::mutex`) вокруг общих структур
  (`authTokens_`, `activeUsers_`, кэш базы, rate limiter) — event loop сам
  не прерывает корутину посередине синхронной операции, так что гонок нет.
- **SHA-256**: вместо самописной реализации используется `hashlib.sha256`
  из стандартной библиотеки — тот же алгоритм, тот же результат
  (`hash(password + salt)` в hex), но без переизобретения колеса.
- **Токены**: `secrets.token_hex(16)` вместо `std::random_device` — тот же
  формат (32 hex-символа = 128 бит), но криптографически более надёжный
  источник случайности.
- **Всё остальное** (валидация полей, коды ошибок `reason`, лимиты длины,
  формат сообщений в JSON, поведение rate limiter'а, формат JSON-базы данных)
  сохранено один в один — существующий клиент не должен заметить разницы.

## Известные особенности (перенесены из оригинала как есть)

- Хранение пароля как `sha256(password + salt)` — быстро подбирается
  брутфорсом по сравнению с bcrypt/scrypt/argon2. Если нужно усилить —
  замените реализацию `hash_password()` в `security.py`.
- `logout` не инвалидирует остальные токены пользователя, если он был
  залогинен с нескольких клиентов одновременно — так было и в оригинале.
- База — плоские JSON-файлы, не рассчитанные на большие объёмы данных;
  при необходимости стоит перейти на SQLite/PostgreSQL, интерфейс
  `JsonDatabase` в `database.py` можно заменить на аналогичный класс.
